# Agent 会话关闭

Agent Operations 在所选会话的活动/计算标签页上方提供“关闭会话”。确认框显示
会话名称和 ID，明确告知关闭后不能重新打开、历史记录保留。此组件由 Web 与
原生 Flutter 页面共用；本增量不包含原生打包或设备安装验证。

只支持声明 `session_close_supported: true` 的在线实例。旧 Gateway 缺少该字段时
禁用关闭；`session_capacity: 0` 不影响已存在会话的关闭能力。UI 对已知活动 turn、
计算任务和未确认提交禁用关闭，Hub 在事务中重新执行最终授权和空闲准入。
用户权限继续使用 `agent.sessions:write`；查询需要 `agent.sessions:read`，租户、
实例 grant 与开启时的身份资格检查由服务端负责。此权限是实例管理权限，并非
只允许创建者管理自己的会话。

## 请求和恢复

- `POST /api/v1/agent/sessions/{session_id}/close`，空 JSON 对象、无 query，携带
  必需的 `Idempotency-Key`。收到 202 后保存请求 ID。
- 已受理请求只通过 `GET /api/v1/agent/session-close-requests/{request_id}` 跟踪，
  两秒查询一次；查询失败暂停，使用“重试状态”恢复 GET，绝不重复 POST。
- 网络失败、401、非法或目标不符的响应可能发生于服务端已受理之后。保留同一
  目标和 key，只有用户选择“重试同一请求”才再次 POST。未知结果之后即使遇到
  403 等拒绝也不清除原 key，不能改为另一会话。
- 关闭确认框不会终止跟踪。每个 Agent Operations 页面只保留一个关闭流程；
  离开页面、刷新或重新登录会丢失这份内存恢复状态，未实现跨登录持久恢复。
- 返回 `queued` 表示容量仍然占用；只有 Gateway 确认运行时关闭成功并由 Hub
  记录 `closed` 后才释放。`failed` 保持会话不可用、容量占用，需重启 Gateway
  恢复；`lost/owner_replaced` 表示实例替换前未确认，不冒充关闭成功。

## 历史与并发

关闭接受后会话冻结。列表、消息、turn 和计算历史继续可读；编辑器与新计算提交
禁用。未知 POST 的目标也暂时禁止新提交，避免把新工作投入可能已经关闭的会话。
会话的历史创建回执保持 `created`；关闭状态属于独立关闭请求。

关闭结果只更新仍然选中的同一会话，不切换用户的选择，也不清空已有消息。
迟到的旧令牌 401 不删除后续登录保存的新默认或其他 client 凭据。错误文案使用
固定中英文映射，不显示 Gateway 原始诊断或令牌。

API 对关闭回执执行严格字段、ID、结果/错误组合和有限时间戳校验，响应上限为
32 KiB；会话和请求 ID 必须匹配原请求。该页面不提供删除历史、强制取消、重开
会话或迁移操作。
