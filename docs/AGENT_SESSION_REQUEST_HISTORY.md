# Agent 会话请求记录

在 Agent 运维页选择实例，打开“会话请求记录 / Session requests”。入口也适用于
没有会话的实例和离线实例；已选择会话时可直接查看它所属实例的请求。
弹窗固定当前实例。要查看其他实例，关闭弹窗后切换实例。

页面读取 Hub 已受理的创建与关闭请求，因此重新登录、换设备或重新打开应用后，
具有该实例 `agent.sessions:read` 权限的用户仍能查看请求状态。请求列表不按提交者
或客户端区分；租户和实例授权由 Hub 决定。不会显示原幂等键、凭据、执行器身份、
本地会话 ID 或项目路径。

- “刷新最近记录”读取最新一页；“更早的请求”读取下一页，每页默认最多 20 条。
  页面只保留当前页，不会自动循环拉取全部历史。
- 选择记录可查看操作、状态、名称/目标会话和请求 ID。“刷新请求状态”使用原创建
  或关闭请求的详情 GET，不发起创建、关闭或重试 POST。
- 请求具有会话 ID 时，可显式“打开会话”。这会读取对应会话并校验实例和会话 ID；
  关闭弹窗、改选会话或登录身份变化后的迟到响应不会切换当前选择。
- 空列表、排队中、成功、失败、实例重启导致结果丢失及读取失败均有提示；读取失败
  可以手动重试。旧 Hub 返回 404/405/501 时提示尚不支持请求记录，其他功能仍可使用。
- 账号上下文变化后，正在读取的旧请求页及详情会被清除；请关闭弹窗，登录后重新打开。
  旧响应不能清除后来保存的默认或按客户端隔离的凭据。

本地尚未确认的创建/关闭请求仍使用原有内存恢复流程。请求记录不会接管、替换或
持久化它们的幂等键，也不能恢复 Hub 从未受理的输入。“打开会话”只查看已有会话；
已关闭会话的历史保持只读，不会重新激活运行时。

## 接口边界

共享 Flutter 代码使用单次、认证的
`GET /api/v1/agent/session-operations?instance_id=...&before=...&limit=20`。
客户端校验精确的 `data` / `next_cursor` 信封和九字段记录、固定状态/错误码、
有限非负时间戳、实例绑定、页大小、重复请求身份和重复游标，响应上限为 256 KiB。
游标作为不透明 base64url 字符串传递，最多 2048 字符，不解码、不展示。
标识符遵循 Hub 的最多 256 Unicode 字符、首尾无空白、无 C0/DEL 规则，允许合法
C1 字符；创建名称仍采用 256 UTF-8 字节与 Unicode Cc/Cf 限制。

详情刷新复用 `/session-requests/{id}` 或 `/session-close-requests/{id}`，并再次
校验操作、请求、实例、创建时间和不可变名称/已知目标。分页依据请求创建时刻排序，
状态变化不改变位置；这是实时历史而不是固定快照。新请求通常通过刷新最近记录查看，
时钟回拨时应刷新并重新浏览相关时间段。

共享界面有中英文和窄屏覆盖。本增量不涉及原生打包、设备安装或线上部署；
验证范围和基线问题见 `AGENT_SESSION_REQUEST_HISTORY_VERIFICATION.md`。
