## 3. Requirements (landed state, module `lib/screens/admin`)

### REQ-1 — Server-side read is the only evidence surface for the timeline
`AuditLogTab` fetches `GET /api/v1/audit/events` through the injected `SnaplinkAdminApi` (via `AuditReadClient.list(limit: 100)`, `lib/api/audit_read_client.dart:51`) on `initState` and on every refresh (`audit_log_tab.dart:53-54,63,285,319`). Displayed rows, the `{count} entries` header (`:287`), the error-rate badge (`:217-254`), CSV export (`:169-211`), the empty state (`:420`), and the subtitle (`:284`) derive from the server response only. `AuditLogService().entries` is never consulted for any of them.

### REQ-2 — Dependency injection
`AuditLogTab` takes `required SnaplinkAdminApi api` and `required SnaplinkAdminCapabilities capabilities` (`:23-26`), same shape as `GovernanceTab` (`governance_tab.dart:16-19`). No self-constructed API client, capability set, or `AuditLogService` for display data. Dashboard binds both from its existing `_api`/`capabilities` (`dashboard_screen.dart:82,244`) and registers the tab under `if (navigation.supportsAuditLog)` with `page: AuditLogTab(api: _api, capabilities: capabilities)` (`:559-567`).

### REQ-3 — Request parameters (bounded, AuditQuery-mandated, deterministic)
- Wire is exactly `{'limit': '100'}` per request — built by `AuditQuery(limit: 100).toQueryParameters()` (`lib/api/audit_read_client.dart:42-51`); no hand-built query maps (guard scan 5, E7).
- `tenant_id` and `trace_id` are **not sent**: the tab constructs `AuditReadClient(widget.api)` with no context (`audit_log_tab.dart:35-37` comment: "nothing is passed today (D3)"; B4-1/BFF mechanisms are `[PROPOSED]`, §5).
- Search/filter terms never ride the URL: every request, including search-triggered re-queries, carries exactly `{'limit': '100'}`; filtering/sorting is client-side over the fetched page (`_applyFilter` `:115`, `_sortRows` `:132`).
- Cache: the `query != null` branch of `SnaplinkAdminApi.get` never consults/populates/dedups the cache (E5) — every refresh is a fresh server read.

### REQ-4 — Capability gate, no catalog fallback
`_refresh` first checks `widget.capabilities.has('GET', AuditReadClient.eventsPath)` (`:68`); on absence it invalidates any in-flight fetch (`_generation++`), clears rows/error/loading, and renders `'This feature is not enabled on the connected replica.'` (`:271`) with **zero requests**. This deliberately differs from `governance_tab.dart:80-91` (`_has` falls back to `SnaplinkAdminOperationCatalog.endpoints`): the audit timeline never guesses interfaces from the static catalog.

### REQ-5 — Ring references confined to the debug-only surface (B6-1b boundary)
The only `AuditLogService` references in `audit_log_tab.dart` are the B6-1b debug badge — `_logService` (`:33`, badge count at `:227-244`) and the `kDebugMode && AuditLogService.ringCopyEnabled` gate (`:293`) — plus the Clear action (`:307-318`) which clears the ring and re-fetches server truth. All are `kDebugMode`-folded out of release bundles (E18). Ring rows never render on the timeline and the ring never acts as a fallback on server error/empty (AC-3).

### REQ-6 — Stale-response safety
`_generation` (`:60`) guards commits: only the newest fetch may write state; an older in-flight response is discarded (FM-9 pinned). The capability-gate path also bumps `_generation` so a stale response can never commit over the not-enabled state.
