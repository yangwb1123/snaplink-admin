## 3. Requirements

### REQ-1 — Zero-audit-reference floor (static guard; module invariant)
`lib/screens/developer/**` must keep **zero** references to `AuditLogService`, `audit_log_service`, and the ring key `sso_audit_log` — no imports, no construction, no reads, no writes, no string literals. This is the module-side encoding of "localStorage ring → debug-only recording" (`implementation-gate.md:56`): DCR mutations are evidenced exclusively through the server feed. Verified compliant at HEAD (E2); enforced by a Dart scan test (AC-2) plus the CI grep guard (AC-4).

### REQ-2 — DCR mutations leave the ring untouched (net-zero behavioral isolation)
Driving the module's three client-lifecycle mutations through `DeveloperApi` — `register` (POST `/register`), `saveApp` (PUT `/register/:client_id`), `deleteApp` (DELETE `/register/:client_id`) — must have **bit-identical** effect on the ring:
- `LocalStorage.keys()` must not gain `'sso_audit_log'` as a result of any mutation;
- `LocalStorage.getItem('sso_audit_log')` must be byte-for-byte identical before and after (exact string equality);
- `AuditLogService().count` and `.entries` must be identical (same count, same instances, same order) — because `record()` mutates `_entries` in memory before `_save()` (S2), the in-memory comparison catches a transient write-then-restore of localStorage;
- the developer HTTP surface must issue **no** request to any audit endpoint — the MockClient's recorded request paths must be exactly the three DCR paths (mirrors the sibling's "no audit request from the login flow" assertion, E3).

### REQ-3 — Forge-invisibility (T-12 joint: devtools-forged ring rows are never evidence)
The server-fed timeline (landed B6-1a `AuditLogTab`, E6) renders server rows only. A pre-seeded forged ring entry whose vocabulary **matches** a server row (forged `label` == a server row's `type`, path naming the same resource) must: never render as a row, never merge with or duplicate the server row (`findsOneWidget`, never `findsNWidgets(2)`), never appear as fallback content, and never be written to by the timeline itself. This extends the landed admin joints (S3, non-matching path) with the matching-vocabulary dedup/misattribution variant, pinned from the developer suite.

### REQ-4 — Joint test contract (guard shapes mirror the oidc_login sibling)
- The net-zero test (AC-1) mirrors `test/oidc_login_ring_isolation_test.dart:104-137` step-for-step: pre-seed → post-seed snapshot (with seed-sanity asserts) → drive → assert untouched → `addTearDown(AuditLogService().clear)`; the drive is the `test/developer_api_test.dart` MockClient harness (E7) and needs no widgets (S1, S2).
- The literal-scan test (AC-2) mirrors `test/oidc_login_audit_visibility_guard_test.dart:21-47` with the scan root swapped to `lib/screens/developer` and the same literal-split needles (`['AuditLog' 'Service', 'audit_log_' 'service', 'sso_audit_' 'log']`) so the guard file can never trip its own scan.
- The forge-invisibility test (AC-3) compiles against the **landed** `AuditLogTab` surface (`required api`/`required capabilities`, `audit_log_tab.dart:26-27,40`) and the `SnaplinkAdminApi` carrier (S5) — no `[PROPOSED]` BFF/`trace_id`/`tenant_id` wire, no interface guessing.
- Deliverable is guards + tests only: **zero production-code change** in `lib/` (module already compliant, E2).
