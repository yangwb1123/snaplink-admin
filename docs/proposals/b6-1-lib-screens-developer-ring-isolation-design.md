### 0.2 Findings that sharpen the acceptance contract (no spec defect — design-level clarifications)

**N1 — `AuditEntry` has no `operator ==`; the AC-1 `entries` equality is identity-based and that is the point.** `entries` returns `List.unmodifiable(_entries)` — a fresh wrapper per call — so `expect(AuditLogService().entries, entriesBefore)` passes only through package:matcher's deep collection equality, which compares element-wise and falls back to **instance identity** for `AuditEntry`. Consequences: (a) the assertion is the strongest possible write-then-restore detector — any transient `record()` inserts a fresh instance that can never be identity-equal; (b) it is a matcher-semantics dependency, not an `AuditEntry.==` dependency; if a future change adds value-based `==` to `AuditEntry`, the pin weakens to value equality (still catches label/path/count changes, but no longer "same instances"). Robustness invariant (re-verified at HEAD `audit_log_service.dart:89-94, 137-145`): `record()` stores the **caller's instance directly** — no JSON round-trip — so identity survives `_save()`; `_load()` is the **only** code path that re-creates instances (`AuditEntry.fromJson`). Therefore write-then-restore cannot launder identity: even a mutation that restores the exact stored JSON afterwards leaves a `fromJson`-fresh instance in `_entries`, which is not identical to the seed instance. Layered defense: should a future `AuditEntry.==` weaken this pin to value equality, the storage-level asserts (F2 keys-set, F3 stored-string) still catch the write. The new tests must document this; the guard's reason string must say "same in-memory entry instances".

**N2 — the header count is `_rows.length`, not the wire `count` field** (`audit_log_tab.dart:287`). AC-3's `'2 entries'` assertion requires the canned body to contain **exactly two rows**; the wire `count` value is irrelevant to the header (sibling AC-3a already proves this: body `count: 999`, header `'2 entries'`). The coupling is **intentional and the point of the assertion**: it pins that the header derives its count from the decoded events array (`_rows.length == 2`), not from the wire's `count` — a future commit that merges ring rows into `_rows` flips it to 3 and fails `findsOneWidget` (F7). The assertion must carry `reason: 'header count derives from _rows.length (2 rows), never the wire count or the ring'`.

**N3 — a server row's `type` renders in exactly one widget: the bold EVENT cell** (`TableCellText(_displayed[i].type, bold: true)`, `audit_log_tab.dart:447`). There is **no path column** on the timeline (the CSV export header at `:171-176` is `timestamp,type,outcome,id,actor_id,client_id,tenant_id` — no path). So AC-3's `find.textContaining('/api/v1/admin/clients') → findsNothing` is trivially green today (paths never render) and exists purely to pin the future hazard: a buggy commit that merges ring rows into `_rows` would render the forged **label** as a duplicate `admin_client_created` (caught by `findsOneWidget`) and, if it also added a path column or debug row, the path (caught by `findsNothing`). **This assertion is a FUTURE-PIN, explicitly non-current-behavior**: it must be marked in the test file with a comment (`// FUTURE-PIN (non-current-behavior): no path column renders today — do not delete as dead; it trips when a future commit renders ring paths`) and in the reason string, so maintainers cannot "simplify" it away as trivially-green. Deleting it today is a no-op; deleting it later silently removes the merge-hazard tripwire.

**N4 — the B6-1b debug badge is ON by default in `flutter test`** (`_ringCopyEnabled = kDebugMode`, `audit_log_service.dart:76`; `flutter test` runs in debug mode). The badge (`_debugRingBadge`, `audit_log_tab.dart:236-247`) renders exactly two visible texts — `'Debug records'` and `'Debug records: {n} entries'` (n = `_logService.count`, i.e. 1 after the AC-3 seed) — plus a delete icon whose tooltip is `'Clear local debug records'`: **count text only, never paths or labels**. AC-3 needles (`admin_client_created`, `/api/v1/admin/clients`, `forged`) cannot collide with badge text; `find.text('2 entries')` (exact) also cannot collide with `'Debug records: 1 entries'`. The design does **not** toggle `ringCopyEnabled`/`debugRingEnabled` — keeping the default exercises the real debug surface (the sibling AC-3a suite passes 18/18 with the badge default on).

**N5 — AC-1's drive produces three requests but only two distinct paths.** POST → `/register`; PUT → `/register/client-1`; DELETE → `/register/client-1` (PUT and DELETE share the path; only the method differs). The audit-surface assertion must therefore be: request count == 3 **and** every recorded path starts with `/register` **and** no path contains `/api/v1/audit` — not a set-equality over three distinct paths (that would be unsatisfiable by construction).

**N6 — per-isolate shared state: teardown is mandatory.** `AuditLogService()` is a process singleton and VM `LocalStorage` is a module-level map. Every test that seeds the ring must `addTearDown(AuditLogService().clear)` (sibling pattern), and AC-3 must additionally assert `LocalStorage.keys()` unchanged **post-pump** (the timeline must not write). `DateTime.now()` seeds are inert — timestamps are never compared.

## 2. Compatibility constraints

1. **Zero `lib/` edits** — the deliverable is guards + tests (spec §5). Any design that requires touching `developer_api.dart` or `audit_log_tab.dart` is out of contract.
2. **Guard needle set is exactly the three ring literals** — `AuditLogService`, `audit_log_service`, `sso_audit_log` (joined forms). The guard must **not** ban bare `LocalStorage` (the module's legitimate storage use is not the ring; the oidc sibling made the same scoping correction in D3).
3. **Literal-split needles in the guard file** (`'AuditLog' 'Service'`, `'audit_log_' 'service'`, `'sso_audit_' 'log'`) so the guard file can never trip its own scan — and, because `test/` files are scanned by the sibling oidc **census** pattern, the split form also keeps the new developer files out of any future test-site census (sibling D5 lesson). The new AC-1/AC-3 files must likewise avoid the joined literals outside string comments where feasible; the split form in reason strings is the convention.
4. **`@TestOn('vm')` + `dart:io` for the scan test only** (AC-2). AC-1/AC-3 run on the default VM test runner (plain `test()` for AC-1; `testWidgets` for AC-3); the VM in-memory `LocalStorage` keeps AC-1 deterministic (S2).
5. **AC-3 pump environment** must replicate S4 `_pump` **verbatim** (re-verified at `audit_log_tab_test.dart:57-65`): the canonical replication target is exactly
   ```dart
   Future<void> _pump(WidgetTester tester, Widget child) async {
     tester.view.physicalSize = const Size(1200, 2200);
     tester.view.devicePixelRatio = 1.0;
     addTearDown(tester.view.reset);
     await tester.pumpWidget(MaterialApp(home: Scaffold(body: child)));
     await tester.pumpAndSettle();
   }
   ```
   Note the sibling `_pump` deliberately has **no localization delegates** — `LocalizedText` resolves the English default, which is what `find.text('2 entries')` and the needle asserts bind against (the zh variant `_pumpZh` is out of scope for this file). The timeline's 100-row table overflows an 800×600 default viewport; the enlarged viewport is what makes row text findable.
6. **Teardown discipline (N6) — mandatory, sibling-verbatim ordering**: every test that seeds the ring calls `addTearDown(AuditLogService().clear)` **immediately after the seed, before any snapshot or pump** (oidc sibling `:113`; `audit_log_tab_test.dart:90-91`). `clear()` empties `_entries` and calls `_save()`, which rewrites the VM map key to `'[]'` — so one teardown restores **both** the process-singleton and the module-level VM `LocalStorage` map. Because `addTearDown` callbacks run even when an earlier assertion fails, a test that fails mid-body cannot contaminate the next test in the isolate. AC-3 must additionally snapshot `LocalStorage.keys()` pre-pump and assert equality post-pump (the timeline must not write).
7. **No contract literals** beyond existing test vocabulary (`'client-1'`, `'rat-1'`, `'https://sso.example'` match `developer_api_test.dart` conventions); no `trace_id`/`tenant_id` wire, no BFF imports (out of scope per spec §5).
8. **kDebugMode badge stays on (N4)** — no `ringCopyEnabled` toggling in the new tests; assertions are chosen to be badge-immune.
9. **Assertion semantics (N1)** — AC-1's `entries` equality is matcher deep-equality over element identity. Document this in the test comment so a future `AuditEntry.==` addition is reviewed against the pin's intent ("same in-memory entry instances", REQ-2). The comment must also record the robustness invariant: `record()` stores the caller's instance (identity survives `_save()`); only `_load()` re-creates instances — so identity is the strongest write-then-restore trace.
