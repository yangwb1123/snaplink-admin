## 1. Problem statement (verified)

The contract (`docs/campaigns/implementation-gate.md:56`, console row 1: 读路径接入 F-06, T-12 joint) requires the audit timeline page to call the sink read API (tenant_id + trace_id via BFF) and display server-side records; "devtools 伪造不再构成证据". Today:

- `lib/screens/admin/audit_log_tab.dart` (345 lines) renders **only** `AuditLogService().entries` — the localStorage ring (`lib/services/audit_log_service.dart`, storage key `sso_audit_log` at `:66`, sole writer `_recordAudit` in `lib/api/snaplink_admin_api.dart:81`, called only at `:324` for non-GET 2xx). The tab has **no** `api`/`capabilities` constructor parameters, no server read, and ring-derived count/error-rate/CSV/Clear.
- `dashboard_screen.dart:560-567` registers the auditLog entry **unconditionally**: `page: const AuditLogTab()` at `:566`, while every sibling tab follows the capability-driven pattern (`page: GovernanceTab(api: _api, capabilities: capabilities)` at `:557`; `if (navigation.supportsX)` guards around ~15 optional entries at `:275-547`). `AdminNavigationCapabilities` (`lib/screens/admin/admin_navigation.dart:49-144`) has no `supportsAuditLog` getter.
- The only server read is ad hoc inside `governance_tab.dart:167-191` (`_queryAudit`): `widget.api.get(_auditPath, query: parameters)` at `:183` via `AuditQuery` (`:172,:177`), gated by `_has('GET', _auditPath)` at `:400`.
- `lib/api` has **no typed client** for the documented audit trio (`GET /api/v1/audit/events`, `GET /api/v1/audit/facets`, `GET /api/v1/audit/events/{id}` at `snaplink_admin_types.dart:310-312`). `portal_api.dart` (the contract-named BFF path) exposes no audit surface (`:56-60,:180-265` — only the /me-family, notification stream, /logout); its scope is `[PROPOSED]` (`docs/proposals/audit-contract-batch-snaplink-console.md:6`).
- Guard scan 5 (`test/audit_contract_guard_scans.dart:233-260`, group at `test/audit_contract_guard_test.dart:163-176`) already anticipates "B6-1a's AuditLogTab lands" and requires any audit query to be constructed through `AuditQuery` — hand-built `query: {'limit': '100'}` maps trip it.
- `tenant_id` (token-claim derivation) and `trace_id` (BFF injection) are **not evidenced** in this repo: no tenant-claim parser exists in `lib/` (only tenant CRUD paths, response-field reads, and caller-supplied query-param precedents), and the only `trace_id` occurrence is a **response** read at `lib/api/setup_api.dart:215`. Both depend on B4-1/BFF per `docs/proposals/audit-contract-batch-snaplink-console.md:9-11` — therefore the client must **accept them as optional parameters**, never hardcode them.

## 3. Requirements

### REQ-1 — Typed audit read client `AuditReadClient` (the lib/api deliverable)
New file `lib/api/audit_read_client.dart` — a typed, read-only client over `SnaplinkAdminApi` (`snaplink_admin_api.dart:126-134`) whose query construction is exclusively `AuditQuery` (`audit_query.dart`). It is the **single** owner of the audit path literals and the **only** sanctioned way for the audit timeline to reach the sink read API.

- Constructor: `AuditReadClient(SnaplinkAdminApi api, {String? tenantId, String? traceId})` — `tenantId`/`traceId` are **optional context parameters** (E10/E11: no token-claim parser, no BFF injection exist in this repo; B4-1/BFF-dependent). They are **never hardcoded**, never derived, and omitted from the wire unless non-empty after trim (AuditQuery semantics). Per-call overrides may shadow them.
- Path constants (single source of truth, scan-5-safe — see REQ-5): `static const eventsPath = '/api/v1/audit/events';` (and the trio's `facetsPath`, `eventDetailPath`).
- Methods (the documented trio, `snaplink_admin_types.dart:310-312`):
  - `Future<List<AuditEventRow>> list({int limit = 100, String? cursor, String? eventTypes, String? outcome, String? tenantId, String? traceId})` — `GET eventsPath`; the query map is built **only** via `AuditQuery(...).toQueryParameters()`. Default wire exactly `{'limit': '100'}`.
  - `Future<Map<String, dynamic>> facets({...same optional filters})` — `GET facetsPath`, same AuditQuery-mandated construction (thin wrapper; no UI wiring in this direction).
  - `Future<Map<String, dynamic>> event(String id)` — `GET eventsPath/{id}` via `Uri.encodeComponent(id)` (detail-reader precedent `admin_live_events_tab.dart:167`); no query parameters.
- Transport untouched: no new HTTP behavior, retries, auth, cache, or BFF surface in `SnaplinkAdminApi` (REQ-7). `lib/api/audit_read_client.dart` is pure Dart over the existing `get(path, {query})`.

### REQ-2 — Typed row model `lib/api/audit_event_row.dart` (list()'s return type)
Adopt the campaign's validated row model (E15) as the client's typed return: read-only `AuditEventRow` `{timestamp?, type, outcome, id, actorId, clientId, tenantId}` + pure mapper `auditEventRowsFromResponse(Map<String, dynamic>) → List<AuditEventRow>`.

- Primary vocabulary = validated real shape (E14); allowlist redaction (W1.1) — non-allowlisted fields are dropped at row construction; no code path from raw response to a row except through the allowlist.
- Defensive fallbacks only for non-snaplink deployments (legacy `method`/`path`/`status` aliases); never the primary columns.
- Invariants: count-preserving; `outcome == ''` for fallback rows (no fabricated success/failure); never-throw (`is`-only reads, no `as` casts, top-level `try/catch` → fallback row); redact-first via `SensitiveData.redact` + URI-query scrub on legacy URI-shaped strings; `{'events': []}` / `{}` → 0 rows (server-truth empty state).
- No Flutter imports, no prints (unit-testable on the VM).

### REQ-3 — AuditLogTab rewire: server read is the only timeline data source
`lib/screens/admin/audit_log_tab.dart`:

- Constructor becomes `const AuditLogTab({super.key, required this.api, required this.capabilities})` — `SnaplinkAdminApi` + `SnaplinkAdminCapabilities`, same shape as `GovernanceTab` (`governance_tab.dart:23-24`). No self-constructed API client; `AuditLogService` is **not** consulted for the timeline.
- On `initState` and every user-initiated refresh (including search/filter re-queries): `widget.api.skipCache()` (governance precedent `:166`; harmless no-op for query GETs — E14) then `_client.list(limit: 100)`; displayed rows, `{count} entries` (from `_rows.length`, never the response `count` — it is page length, E14/W1.3d), the error-rate badge, CSV export, and the empty state all derive from the **server response only**. Search/filtering stays client-side over the fetched page.
- Stale-response guard: generation counter captured before the request; only the newest fetch may commit rows (out-of-order refresh safety).
- States: loading; error (`error.toString()` only — `SnaplinkAdminApiError.toString()` at `snaplink_admin_error.dart:44` is `description ?? code ?? 'Admin request failed ($status).'`, excludes `data` by construction; never `error.data`) with inline retry that re-enters the gate; not-enabled (REQ-4); server-truth empty.
- Subtitle `:158` ("recorded on this device") and empty-state copy `:244` become server-sourced; new keys land atomically with zh entries (REQ-8).
- Clear-log button behavior and its ring-derived enabled-state are **unchanged** in this direction (demotion/relabeling is the sibling lib/services direction's scope).

### REQ-4 — Endpoint-inventory capability gate (page + entry, honest gate)
- **Page gate:** the read is issued iff `widget.capabilities.has('GET', AuditReadClient.eventsPath)`. Without it: a not-enabled state and **zero requests**. The gate consults the injected `SnaplinkAdminCapabilities` **directly** — it must **not** copy `governance_tab.dart` `_has`'s catalog fallback (`:81-91`), which would make the audit UI unconditionally available (E5 ⚠️) and defeat the direction's hiding clause. The gate predicate mirrors governance's `:400` shape (`has('GET', '/api/v1/audit/events')`) but without the fallback — this is the one deliberate, documented deviation; the tab receives the merged view from the dashboard, so production behavior is unaffected.
- **Entry gate:** add `bool get supportsAuditLog => _has('GET', '/api/v1/audit/events');` to `AdminNavigationCapabilities` (`admin_navigation.dart:49-144`, sibling `supportsX` pattern at `:71-144`; module id `AdminModuleId.auditLog` at `:41`), and wrap the auditLog `AdminNavigationEntry` (`dashboard_screen.dart:558-567`) in `if (navigation.supportsAuditLog)` — the standard cull pattern of ~15 sibling entries (`:275-547`).
- **Merged-view honesty:** `AdminNavigationCapabilities` merges the documented catalog by default (`:56-63`), so in production the trio is always present and the entry stays offered. The **absence** half is simulated with `AdminNavigationCapabilities(endpoints, documentedEndpoints: const [])` (constructor already supports it) — an inventory without the audit trio hides the tab. Predicate equivalence by construction: `navigation.supportsAuditLog == navigation.capabilities.has('GET', '/api/v1/audit/events')` for the same endpoint set.
