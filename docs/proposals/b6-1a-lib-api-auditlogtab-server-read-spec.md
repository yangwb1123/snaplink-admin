## 1. Problem statement (verified)

`lib/screens/admin/audit_log_tab.dart` renders only `AuditLogService().entries` — the localStorage ring (`lib/services/audit_log_service.dart`, storage key `sso_audit_log` at `:66`; sole writer `_recordAudit` in `lib/api/snaplink_admin_api.dart:81`, called only at `:324` for non-GET 2xx responses). The tab never calls the sink read API, so T-12 ("查询触发 self-audit 行；devtools 伪造不再构成证据", `docs/campaigns/implementation-gate.md:56`) cannot pass: a devtools-forged ring row is displayed as truth.

Dashboard wiring is still `page: const AuditLogTab()` at `dashboard_screen.dart:566` with no `api:`/`capabilities:` injection (contrast `GovernanceTab(api: _api, capabilities: capabilities)` at `:557`). `lib/api` already has every primitive: `SnaplinkAdminApi.get(path, {query})` (`:126-134`, query branch `:134` bypasses cache), typed `AuditQuery` (`lib/api/audit_query.dart`, default wire exactly `{'limit': '100'}`), and the audit trio in the documented routes catalog (`snaplink_admin_types.dart:310-312`). Yet no typed read model exists in `lib/api` (`audit_event_row.dart` absent), no `supportsAuditLog` capability getter exists (`lib/screens/admin/admin_navigation.dart:71-144` — a dozen `supports*` getters, none for audit), and guard scan 5 (`test/audit_contract_guard_scans.dart:222-260`) trips any hand-built `query: {'limit': '100'}` literal — `AuditQuery` is mandatory for the new consumer (only `governance_tab.dart` uses it today: `:31` path, `:172/177/183` query construction).

**Carrier decision (recorded, not guessed):** the validated read path is `SnaplinkAdminApi`, not `PortalApi`. `implementation-gate.md:56` names `lib/api/portal_api.dart`, but `audit-contract-batch-snaplink-console.md:6` marks that scope `[PROPOSED]`: `PortalApi` (`portal_api.dart:37`, constructor `:45`) is a portal-only client — instantiated solely at `portal_screen.dart:90` — with no audit read method. The B6-1a carrier is therefore `SnaplinkAdminApi`, and the AC-3.2 `bff-literals` scan (`test/audit_contract_guard_test.dart:101-123`) forbids any `bff` literal in `lib/`. See §5 (decision record).

**Response schema risk (recorded):** `docs/backend-contracts.json` contains **zero** audit endpoint records (grep: only prose uses of "audited"). The real response shape was however **validated against the server implementation** in the sibling repo (`b6-1a-validation-audit-events-response-shape.md`): envelope `{events, count}` (OpenAPI `AuditEventList`, `required: [events, count]`; `count` = page length), per-event fields `{id, type, outcome, timestamp, actor_id, client_id, tenant_id, …}` — the server emits **no** `method`/`path`/`status`/`event_type`/`time`. The row mapper (`lib/api/audit_event_row.dart`) is therefore a **defensive mapping over a validated shape** — the allowlist is real, the fallbacks are defensive (`[REV-3]`: the previous revision's REQ-4, which listed ring vocabulary first, is corrected).

## 3. Requirements

### REQ-1 — Server-side read is the only data source for the timeline
`AuditLogTab` must fetch `GET /api/v1/audit/events` through the injected `SnaplinkAdminApi` on `initState` and on every user-initiated refresh (including search/filter re-queries; search/filtering stays client-side over the fetched page). Displayed rows, the `{count} entries` counter, the error-rate badge, CSV export, and Clear-log must derive from the **server response only**; `AuditLogService().entries` must not be consulted for the timeline. The subtitle at `audit_log_tab.dart:158` ("recorded on this device") is replaced with server-sourced copy (e.g. "All authentication and administrative events recorded by the server.") — display truth is the server record. The empty state is likewise server-sourced. Debug-only relabeling of CSV/Clear and ring demotion belong to B6-1b (§6).

### REQ-2 — Dependency injection
`AuditLogTab` must accept `required SnaplinkAdminApi api` and `required SnaplinkAdminCapabilities capabilities` constructor parameters — same shape as `GovernanceTab` (`governance_tab.dart:16-19`). The tab must not construct its own API client or capability set, and must not construct `AuditLogService` for the timeline.

### REQ-3 — Request parameters (bounded, evidence-graded, AuditQuery-mandated)
- **Established (required):** `limit=100` (governance precedent `{"limit": 100}`, `governance_tab.dart:33`; sink `NormalizedLimit()`: 0/neg → 100, >1000 → capped — `limit=100` is in-bounds).
- **Mandatory construction path:** the query map must be built via `AuditQuery(limit: …).toQueryParameters()` — scan 5 (`test/audit_contract_guard_test.dart:152-176`) trips on any hand-built query map against `/api/v1/audit/events` or `/api/v1/audit/facets`. No literal `{'limit': …}` maps on audit paths.
- **Established (required, deterministic):** no query parameter may be derived from a token claim (no claim parsing exists in-repo, E6).
- **Proposed (conditional — only if the injected api/caps expose them):** `tenant_id` (caller-supplied query-param precedent exists) and `trace_id` (no injection mechanism exists; BFF/B4-1 dependency per E6). Default: **omit both**, preserving the exact `limit`-only wire (`audit_query_test.dart` AC-1.1). The conditional branch, if ever implemented, is explicit and exercised only when the injected api/caps provide the context — never a silent any-params wire. Any future query-param addition is a proxy-log leakage review point (search terms/event content must never ride the URL).

### REQ-4 — Typed row model + response-to-rows mapping (the lib/api deliverable)
New file `lib/api/audit_event_row.dart`: a read-only typed row model plus a pure, unit-testable, never-throwing mapper.
- **Primary vocabulary (validated real shape, E15):** `id`, `type`, `outcome`, `timestamp`, `actor_id`, `client_id`, `tenant_id` — the direction's §1.1 field allowlist. Every other real field (`request_id, trace_id, span_id, parent_span_id, actor_ip, user_agent, provider, session_id, token_id, token_strategy, reason, metadata, prev_hash, hash, server_version`) is **dropped at row construction** — redaction by allowlist; no code path from the raw response to a row exists except through the allowlist.
- **Defensive fallbacks only (legacy ring vocabulary):** `method`/`verb`, `path`/`resource`/`endpoint`/`uri`, `status`/`status_code`/`statusCode`, `label`/`event_type`/`event`/`action`/`time`/`created_at` aliases map for non-snaplink deployments — never the primary columns. Missing values render safe placeholders (null timestamp → `--`; status 0 → `-`; empty method → `-`; label falls back to id/type, then `'audit event'`).
- **Invariants:** count-preserving (N records in → exactly N visible rows, never a silent drop); `outcome == ''` for fallback rows (never a fabricated success/failure signal); a row with neither path nor label still renders one visible row.
- **Never-throw/never-leak:** `is`-only field reads (no `as` casts), top-level `try/catch` returning a fallback row; URI-shaped legacy `path`/`label` strings are query-scrubbed per design §1.1 rule 3a (sensitive query params → `<redacted>`) before display/export.
- **Envelope:** list extraction `events` first, with `items/results/data/entries` as defensive aliases; `{'events': []}` → 0 rows (server-truth empty state, AC-2).

### REQ-5 — Capability gate (entry + page, honest gate)
- **Page gate:** `AuditLogTab` issues the read iff `capabilities.has('GET', '/api/v1/audit/events')` (`SnaplinkAdminCapabilities.has`, `snaplink_admin_types.dart:94`). Without it: a "not enabled" state and **zero requests**. The gate consults the injected `SnaplinkAdminCapabilities` directly — it must **not** copy `governance_tab.dart` `_has`'s catalog fallback (`:80-91`), which makes the audit UI unconditionally available (E7); AC-3's zero-request half is only meaningful without the fallback.
- **Navigation gate:** add `bool get supportsAuditLog => capabilities.has('GET', '/api/v1/audit/events');` to `AdminNavigationCapabilities` (`lib/screens/admin/admin_navigation.dart:49-144`, following the existing `supports*` pattern; named `supportsAuditLog` per design hardening pass 4 S12 — the module id is `AdminModuleId.auditLog` at `:41`), and wrap the auditLog entry in `dashboard_screen.dart:566` with `if (navigation.supportsAuditLog)`. `AdminNavigationEntry` is reused unchanged.
- **Merged-view honesty:** `AdminNavigationCapabilities` merges the documented catalog by default (`:56-63`), so in production the trio is always present and the entry stays offered. The **absence** half of AC-3 must be simulated with `AdminNavigationCapabilities(endpoints, documentedEndpoints: const [])` — the constructor already supports this (E13). No new endpoint, no fourth audit path, no non-GET method may be added (AC-3.3 trio scan, E9).

### REQ-6 — Dashboard wiring
`dashboard_screen.dart:566` must become `page: AuditLogTab(api: _api, capabilities: capabilities)` (the `capabilities` binding already in scope at `:244`), replacing `const AuditLogTab()`. Afterwards `grep -n 'const AuditLogTab()' lib/ test/` returns **no hits**.

### REQ-7 — lib/api transport untouched; surface deltas enumerated
`SnaplinkAdminApi.get(path, {query, forceRefresh})` already covers the read (E3). **No changes** to `SnaplinkAdminApi` transport: no new endpoints, retry, auth, cache, or BFF behavior. `_recordAudit` (`:81`) stays untouched (its demotion is B6-1b). The **complete** `lib/api` delta is: (a) new read-only `lib/api/audit_event_row.dart` (REQ-4; no endpoint, no HTTP); (b) no other file. Transport pins that must stay green unchanged: `test/snaplink_admin_api_test.dart`, `test/api_contract_test.dart`, `test/api_paths_test.dart`, `test/sso_client_test.dart`.
