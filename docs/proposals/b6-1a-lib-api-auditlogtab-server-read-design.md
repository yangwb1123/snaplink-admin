## 1. API changes

### 1.1 New file `lib/api/audit_event_row.dart` — typed row model + pure mapper (REQ-4)

**Row model pinned to the VALIDATED server schema** (`{id, type, outcome, timestamp, actor_id, client_id, tenant_id, …}`, `platform/audit/auditspi/event.go`; see `b6-1a-validation-audit-events-response-shape.md`). The server emits **no** `method`/`path`/`status`/`event_type`/`time`/`created_at` — the pre-validation ring vocabulary is demoted to defensive fallback only (W1).

```dart
/// Immutable, server-derived row for the audit timeline.
class AuditEventRow {
  final DateTime? timestamp; // 'timestamp' — null → render '--', sorts last
  final String type;         // 'type' — EVENT column; never empty ('audit event' fallback)
  final String outcome;      // 'outcome' success/failure — STATUS column, error-rate signal
  final String id;           // 'id' — row key (dup/refresh stability)
  final String actorId;      // 'actor_id' — identity column ('' → '-')
  final String clientId;     // 'client_id' — identity column ('' → '-'); B6-2 owns the constant, not the display
  final String tenantId;     // 'tenant_id' — identity column ('' → '-')
  const AuditEventRow({...});
}

/// Pure, defensive mapper. Never throws. Never drops a server record.
List<AuditEventRow> auditEventRowsFromResponse(Map<String, dynamic> response);
```

**[AMEND W1.1 — field allowlist, mandatory]** Every other real field is **dropped at row construction**: `request_id, trace_id, span_id, parent_span_id, actor_ip, user_agent, provider, session_id, token_id, token_strategy, reason, metadata, prev_hash, hash, server_version` — never displayed, never exported, never copied into a row. Key-based redaction cannot scrub free text (`reason`), PII (`actor_ip`, `user_agent`), or benign-key `metadata` values; allowlist exclusion is the only airtight rule. Extraction goes exclusively through allowlisted helpers — no code path from the raw response to a row exists except through the allowlist.

Mapping rules (all per-field fallback, per REQ-4/E13; hardening amendments from adversarial reviews, `hardening-review.md` pass 1 + pass 2):
1. **Redact first, once**: `SensitiveData.redact(response) ?? const {}` before ANY row construction (repo doctrine: generic renderers must redact; the rows feed both the table and the CSV clipboard). Every row is built only from the redacted tree, so a mid-map failure can only drop rows — never expose unredacted data. NOTE: `SensitiveData.redact` is **key-based** (strings pass through, `sensitive_data.dart:34-46`) — redaction alone does NOT protect credentials embedded in path/query strings; rule 3a closes that gap.
2. **List extraction**: first of `['events', 'items', 'results', 'data', 'entries']` whose value is a `List`. If none is a list: **empty map `{}` → `[]` (0 rows — the server-truth empty state must render; never invent a phantom record)**; non-empty bare map → treat as a single record (1 row). Non-map list elements become one fallback row each (`label: 'audit event'`) — never silently dropped, never echoed verbatim.
3. **Field aliases (real shape first)**: `timestamp`/`time`/`created_at`/`createdAt`/`occurred_at` (parse via `DateTime.tryParse`; invalid → null); `type`/`event_type`/`eventType`/`event`/`action`/`label` (never-empty label fallback chain: type → id → `'audit event'`); `outcome` (string, `''` → `'-'`); `id`; `actor_id`/`actorId`; `client_id`/`clientId`; `tenant_id`/`tenantId`. **Legacy ring vocabulary survives only as defensive fallback for non-snaplink deployments (E13)**: `method`/`verb`, `path`/`resource`/`endpoint`/`uri`, `status`/`status_code`/`statusCode` (int, or num/digit-string via `int.tryParse`; else 0) — never the primary columns.
3a. **String-level scrub (H1, mandatory)**: on any allowlisted string that parses as a URI (legacy `path`/`uri`/`resource`, and `label` when URI-shaped), `Uri.tryParse` then rebuild the query keeping only params whose keys are NOT `SensitiveData.isSensitiveKey` (public, `sensitive_data.dart:11`); sensitive params → `<redacted>`. Non-parseable strings pass through unchanged (no throw). Without this, a server-recorded URI like `/api/v1/clients?client_secret=…` leaks into the table **and** the CSV clipboard. Repo precedent for query-secret sets: `hosted_login_models.dart:212+` `privateParameters`. (The real schema has no URI field in the allowlist — this rule protects the fallback path only.)
4. **Never-empty label**: type → id → `'audit event'`.
5. **Never-throw, never-leak structure (H2)**: (a) redaction (rule 1) precedes all extraction; (b) all field reads use `is` checks — **no `as` casts** (an `as` failure throws mid-map and drops later rows); (c) the whole extraction is wrapped in `try/catch` returning a single fallback row on error — never rethrows, and the fallback cannot carry raw sensitive data because it is built from the redacted tree and is constant-built (never echoes raw strings); (d) signature is `Map<String, dynamic> in → List<AuditEventRow> out`; no IO, no Flutter imports, **zero `debugPrint`/`print`** — unit-testable without a widget harness. (`decodeSnaplinkAdminPayload` already coerces non-map/empty payloads to `{}`, `snaplink_admin_error.dart:44-52`.)

**[AMEND W1.3 — display/logging invariants, mandatory]** (a) error state renders `error.toString()` only — `SnaplinkAdminApiError.toString()` is `description ?? code ?? 'Admin request failed (status).'` (`snaplink_admin_error.dart:66-68`) and never includes `data`; the tab **never renders `error.data`**; (b) zero `debugPrint`/`print` of `response`/`rows` in the new tab + mapper code (grep gate in migration step 9); (c) the raw `response` map is **never retained in state** — `_rows` is the only row store (no governance-style `_data['audit']` retention); (d) `{count} entries` ← `_rows.length` (never the response `count` field — it is page length, and `_rows.length` is equivalent only when untruncated).

No change to `SnaplinkAdminApi` (REQ-7): `get(path, query: {'limit': '100'})` is the entire transport surface; no new methods, retries, or auth behavior. The query-param branch already bypasses the cache (`snaplink_admin_api.dart:121-123`), which is correct for a live timeline.

### 1.2a `lib/services/audit_log_service.dart` — `kDebugMode` seam (ring demotion, debug-only storage I/O)

**[AMEND W2 — mandatory seam shape]** `kDebugMode` is a compile-time constant (`const bool kDebugMode = !kReleaseMode && !kProfileMode;`, Flutter SDK `foundation/constants.dart:64`): `if (kDebugMode)` const-folds, and in release/profile AOT/dart2js builds the branch (and the `'sso_audit_log'` string constant inside it) is eliminated by dead-code elimination. The seam gates **both** storage reads and writes with a **runtime `if`** (never `assert` — asserts are stripped in release, which would delete the gate and re-enable the read):

```dart
// Public API unchanged (record/entries/search/filterByMethod/recent/clear/count) —
// service_contracts_test.dart:18-37 and snaplink_admin_api.dart:81/324 stay green.
static bool _storageEnabled = kDebugMode;   // const-folded: always false in release/profile

@visibleForTesting
static set debugStorageEnabled(bool value) {
  if (!kDebugMode) return;  // const-folds to `return;` in release — assignment unreachable
  _storageEnabled = value;
}

void _save() {
  if (!kDebugMode) return;      // DIRECT const guard FIRST (pass 4, S14): DCE rests on
  if (!_storageEnabled) return; // const-branch folding alone — structural, not analyzer-heuristic
  ...
}
void _load() {
  if (!kDebugMode) return;      // same shape
  if (!_storageEnabled) return;
  ...
}
```

Rules: (a) gate `_load()` **and** `_save()` — release must neither read nor write `sso_audit_log`; `record()` keeps the in-memory ring (bounded 1000) so public behavior in memory is unchanged; (b) the test setter is itself const-gated, so **no release code path can enable storage I/O even if it calls the setter** — the assignment is unreachable in release; (c) `kDebugMode` is the **only** enable condition — no `bool.fromEnvironment`/env-var axis (a second axis is a future leak); (d) tests flip `debugStorageEnabled` both ways: `false` simulates release (assert `LocalStorage` untouched — `keys()` empty — while `entries`/`search`/`clear` still work in memory), `true` exercises the ring path; `flutter test` is always debug-mode, so both directions are testable; profile/release integration runs see the inert path by const-folding — that is the required behavior, not a leak; (e) release-artifact proof gate (migration step 9 / `full_stack_verify.py`): after `flutter build web --release`, `grep -r "sso_audit_log" build/web/` → **zero hits** (same grep-gate pattern as AC-4's `const AuditLogTab()`); the gate runs on **release output only** (a debug build legitimately contains the key — `kDebugMode` is on). Leftover `sso_audit_log` storage from before the migration is then provably inert in release: never read, never written, never rendered — and **no `removeItem` migration**: deleting the key would require the literal in release-reachable code and defeat the gate (cleanup is B6-1b's ring-removal step).

**Tree-shaking evidence (pass 4, S14–S16, empirically tested with this repo's toolchain)**: `dart compile js -Ddart.vm.product=true -O4` (the web-release const-environment) on the exact seam shape above — mutable `_storageEnabled` + const-gated setter + `if (!_storageEnabled)` guards — **eliminates `sso_audit_log` from the output** (grep 0). The direct-first `if (!kDebugMode)` guard makes that elimination *structural* (const-branch folding, guaranteed) rather than dependent on dart2js's "no reachable write" interprocedural analysis. **`String.fromCharCodes` fallback — last resort only, never committed source**: tested, it does defeat the grep gate (int array emitted, `fromCharCodes` symbol inlined away) — which is exactly why it must not be the primary mechanism: it can mask a DCE failure, the key stays recoverable from the array, and a gate grepping for `fromCharCodes` would be unreliable. Step-9 gate: `grep -rn "fromCharCodes" lib/services/audit_log_service.dart` → zero hits, so the artifact gate proves *elimination*, not *hiding*. Bypass-vector notes for the artifact gate: non-const string concatenation is grep-missed → source gate `grep -rn "sso_audit_log" lib/` → exactly 1 hit (the single const); no `.map` sourcemaps are emitted today (verified) and `grep -r` covers them recursively if a future build emits them; chunked JS parts and the service-worker manifest are covered by recursive `grep -r` over `build/web/` (key never legitimately appears there).

**Debug-print hardening (pass 4, S9)**: the `_save`/`_load` catch blocks currently print `debugPrint('audit_log persist/load error: $e')` — a `FormatException` from `jsonDecode` embeds a *snippet of the decoded input* in its message, so a devtools-forged ring row with malformed JSON would be echoed to the debug console including any planted sensitive text. Both catches become `debugPrint('audit_log storage error: ${e.runtimeType}')` — constant message + exception type only, never `$e`.

## 6. Self-audit drill spec — `tests/integration/audit_self_audit_drill.py` (W3, cross-repo B1-5 canary)

Verified against the sink repo: the server-side `type` filter is **enforced** (exact-match `type = ?` in SQLite `buildWhere`, `snaplink/platform/audit/sqlite/query.go:49`; `Query.Match` in `auditspi/query.go:38-40`; `parseQuery` binds it at `handlers.go:147`); `actor_id`/`request_id`/`trace_id` are equally server-side filters; `count` in the response is **page length**, never a total; `NormalizedLimit` caps at 1000; event ids are 24-hex random (`auditspi/id.go`) — `id`-based dup detection is sound. **B1-5 (`audit.event.read` emission) is NOT implemented in the sink today** (no EventType constant, no emission path — grep-verified) — the drill is a dependency canary: it stays red until the sink lands B1-5, and every suppression vector is closed.

- **Auth**: login via `/auth/login` (pattern: `full_integration_test.py:46-54`) with a **dedicated** test account (`SNAPLINK_SELF_AUDIT_USERNAME`/`_PASSWORD`, distinct from the console operator's) — required; a shared actor ⇒ refuse to run (exit 1) — exact counting under a shared actor is inherently racy.
- **Sequence** (every query generates exactly one self-audit row, visible only to subsequent queries — T-12 contract): Q0 (query 1, n0 snapshot) → R (query 2, probe read) → Q1… (observation queries). Assert on the `i`-th query: `observed == n0 + (i - 2)` — exact, self-adapting under polling; no auto-retry on counting queries (a retried GET = extra row + miscounted `i`); all queries `limit=1000`, no offset, optional identical `since`.
- **Per-response assertions**: every row `type == 'audit.event.read'` AND `actor_id == <drill identity>` (non-empty) — proves the server-side filter is enforced, not assumed; `len(events) == count`; `len(events) < 1000` else FAIL (truncated count is a lower bound).
- **Dup-id**: within a response `len(set(ids)) == len(ids)`; across snapshots `set(ids(Q_i)) == set(ids(Q_{i-1})) ∪ {exactly one new id}`; the probe's row is fresh (absent from Q0).
- **FAIL-loud, non-suppressible**: zero `audit.event.read` rows ⇒ exit 1 with "B1-5 dependency missing: sink never emitted audit.event.read"; 404 ⇒ exit 1 (audit API not mounted); no `--skip`/`--warn`/env-var escape; no `except: pass`. Wired into `full_stack_verify.py` as **its own `step()`** in section 5 — runs in both `--quick` and full modes, never inside the Playwright `try/except ImportError` block, never piped through `|| true`. `step()` turns any non-zero exit into FAIL + final exit 1 (`full_stack_verify.py:167-168`) — that channel is the suppression-proof enforcement.
