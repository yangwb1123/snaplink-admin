> Source direction: `B6-1 core: route the audit timeline to the server read API (GET /api/v1/audit/events via SnaplinkAdminApi) and demote the localStorage ring to debug-only` (from `docs/auto/analyses/lib-screens-portal-44bdd36d.json`, direction 1).

## 0. Module boundary (why lib/screens/portal)

The module analysis names `lib/screens/portal`, but the direction's decision is **negative**: `lib/screens/portal/portal_api.dart` is a re-export shim of the self-service client `lib/api/portal_api.dart`, and the audit timeline must **not** be routed through it (PortalApi has token-paste login / GET `/me` probe, no admin audit surface). Therefore this direction requires **zero diff in `lib/screens/portal/`** and **zero new audit surface in `lib/api/portal_api.dart`**; the changes land in `lib/screens/admin/audit_log_tab.dart`, `lib/screens/admin/dashboard_screen.dart`, `lib/api/snaplink_admin_api.dart` (debug flag gating), with the test rewrites in `test/admin_support_tabs_test.dart`.

## 1. Problem statement (verified)

`lib/screens/admin/audit_log_tab.dart` renders exclusively `AuditLogService().entries` — a localStorage ring (`lib/services/audit_log_service.dart`, key `'sso_audit_log'` :66, cap 1000 :65) whose only writer is `SnaplinkAdminApi._recordAudit` (`lib/api/snaplink_admin_api.dart:81`, fired on non-GET 2xx at :324). The timeline therefore displays device-forged data as evidence; T-12 ("查询触发 self-audit 行；devtools 伪造不再构成证据", `docs/campaigns/implementation-gate.md:56`) cannot pass. The proven server read exists in `lib/screens/admin/governance_tab.dart` (`widget.api.get('/api/v1/audit/events', query: parameters)` at :183, now typed through the landed `AuditQuery` builder, `lib/api/audit_query.dart`), and the three read routes are documented at `lib/api/snaplink_admin_types.dart:310-312`. The tab has no injected API surface (`lib/screens/admin/dashboard_screen.dart:566` registers `page: const AuditLogTab()` — contrast `GovernanceTab(api: _api, capabilities: capabilities)` at :556) and its header claims events are "recorded on this device" (:158).

## 3. Requirements

### REQ-1 — Portal module boundary: no audit surface in PortalApi (module-level invariant)
- `lib/screens/portal/portal_api.dart` and `lib/api/portal_api.dart` receive **no changes** in this direction — no audit read method, no audit query params, no re-export removal.
- Guard (test): grep-level assertion that `lib/api/portal_api.dart` and `lib/screens/portal/portal_api.dart` contain no `audit` identifier after the change (comment-free count of `audit` occurrences stays 0 in `lib/api/portal_api.dart`; the shim file stays an export-only file). The audit read path is `SnaplinkAdminApi` (`snaplink_admin_api.dart:126` `get(path, query:)`) — the only admin transport with the proven read call (`governance_tab.dart:183`).

### REQ-2 — AuditLogTab gains an injected `SnaplinkAdminApi` (no self-construction)
- `AuditLogTab` constructor becomes `const AuditLogTab({super.key, required this.api})` with `final SnaplinkAdminApi api;` — same injection shape as `GovernanceTab` (`governance_tab.dart:17-24`), minus `capabilities` (capability gating belongs to sibling B6-1a REQ-5/REQ-6; explicitly out of scope here, see §6).
- The tab must not construct its own `SnaplinkAdminApi` and must not read `AuditLogService()` for any display data.
- `_logService` (:22) is removed from the tab; `AuditLogService` remains in the codebase solely as the debug recorder behind the debug flag (REQ-8).

### REQ-3 — Server read is the only timeline source
- On `initState` (:30) and on every user-initiated refresh (refresh button :175, and the header `onRefresh`), the tab calls `widget.api.get('/api/v1/audit/events', query: AuditQuery(limit: 100).toQueryParameters())` — wire query is exactly `{'limit': '100'}` (typed builder already landed, `audit_query.dart:148-164`; sso-server `limit` semantics validated: 0/neg→100, >1000 capped, page = newest-first ≤ limit).
- Search/filter (search field :196-237, method dropdown) stay **client-side** over the fetched rows; they must not re-issue requests and must not place event content/search terms in the URL (proxy-log-safe query surface: `GET /api/v1/audit/events?limit=100` only). No claim-derived params: `tenant_id`/`trace_id` are **not sent** (no claim parsing in repo, E12; `[PROPOSED]` per audit-contract doc).
- The tab does **not** call `/api/v1/audit/facets` or `/api/v1/audit/events/{id}` (those stay governance's surface, `governance_tab.dart:184`).
- Request identity: the existing Bearer header path in `SnaplinkAdminApi._request` (:318 `'Authorization': 'Bearer $accessToken'`) is the caller-identity context the sink attributes self-audit rows to (joint T-12, AC-4).

### REQ-4 — Server rows are the only evidence surface; the ring renders nowhere
- Timeline rows, `{count} entries` (:161), error-rate badge (:129-152), CSV export (:97-125) and empty state (:239-246) derive **only** from the fetched server rows. `AuditLogService.entries`/`count` are never consulted for display — including on server error (no ring fallback: a failed fetch renders the error state, never device data).
- The debug ring stays a debug-only recorder (REQ-8); clearing it must have zero effect on the timeline (AC-2); devtools-forged `'sso_audit_log'` storage values render nowhere (AC-3).

### REQ-5 — Defensive response-to-rows mapping (pure, never drops a record)
Because no in-repo schema exists for `GET /api/v1/audit/events` (E10) and the real sso-server payload is `{events: [...], count}` with event fields `{id, type, outcome, timestamp, actor_id, client_id, tenant_id, ...}` (validated: **no** `method`/`path`/`status` on the real wire), the tab maps via a pure, unit-testable function `List<AuditEntry> auditEventRowsFromResponse(Map<String, dynamic> response)`:
- List extraction: first of `['events', 'items', 'results', 'data', 'entries']` whose value is a `List`; none → `[]` (server-truth empty state; never invent a phantom record); non-map list elements → one fallback row each (never silently dropped).
- Field fallback chain (real server shape first, legacy ring vocabulary as defensive fallback only): `timestamp`/`time`/`created_at`/`occurred_at` (via `DateTime.tryParse`; invalid → null); label ← `type`/`event_type`/`event`/`action`/`label` (never-empty: type → id → `'audit event'`); path ← `id`/`path`/`uri`/`resource` (id is a 24-hex server id, safe to display); method ← `method`/`verb` (absent → `'-'`); statusCode ← `status`/`status_code`/`statusCode` (int/num/digit-string via `int.tryParse`; absent → 0, rendered `'-'`); outcome kept as a displayable string (`''` → `'-'`).
- Never-throw structure: all field reads via `is` checks (no `as`), whole extraction in `try/catch` returning one constant fallback row on error; no IO, no Flutter imports, no `print`/`debugPrint` (unit-testable on the VM).
- Redaction: rows are built from `SensitiveData.redact(response) ?? const {}` first (`lib/services/sensitive_data.dart:55`) per repo doctrine for generic renderers — the rows feed both the table and the CSV clipboard.
- Row rendering: a row with a null timestamp renders `--` in the TIME column (`_formatTime` :270-275 must not throw); rows are never dropped for missing fields.

### REQ-6 — Source label change: server truth + debug-only device marker
- Subtitle (:158) becomes server truth, e.g. `'All authentication and administrative events recorded by the server.'`; the device-ring claim moves to a **debug-only marker** shown only when the debug flag (REQ-8) is active (e.g., a chip/badge next to the header: "device ring active (debug)" — exact copy is implementer-reviewable), so the local ring's existence is visible to developers and invisible to operators.
- Empty-state copy (:244) becomes server-neutral (e.g. `'No server audit events yet.'`), since "Operations will appear here" implies local recording.
- i18n (E14): the two changed keys get their zh entries atomically with the call sites (`app_strings_source_admin_core.dart:56` entry replaced; `app_strings_source_admin_features.dart:142` entry replaced; debug-marker key added to the core catalog). No key may be left dangling (one call site each today).

### REQ-7 — Clear action removed from the primary evidence UI
- The Clear-log action (:179-193) is removed from the primary UI. The timeline must never be clearable by the user; ring clearing survives only as the debug recorder's test/`AuditLogService.clear()` (:101) behind the debug flag — never exposed as a timeline action.
- CSV export (:97-125) remains, operating on the currently displayed server rows, preserving the existing formula-injection guard (`_csvCell` :107-115, `'` prefix for `= + - @` cells) — the CSV regression test is rewritten to server fixtures (AC-6).

### REQ-8 — Debug ring demotion: `_recordAudit` behind a single debug flag
- Introduce one debug flag (e.g., `static bool debugAuditRing = kDebugMode` on `AuditLogService`, or an equivalent single named switch; exact mechanism is the design stage's call) with: default = `kDebugMode` (foundation); test-overridable so **both** branches are assertable in unit tests (a compile-time-only `kDebugMode` cannot be flipped in a debug test run).
- The `_recordAudit(method, path, response.statusCode)` call at `snaplink_admin_api.dart:324` is gated on that flag. Flag on → non-GET 2xx appends to the ring exactly as today (still via `_recordAudit` :81-88 — no new writers); flag off → no append, no `AuditLogService` touch from the API layer. GET responses never record in either mode (unchanged).
- The debug marker (REQ-6) reads the same flag, so the marker and the mutation append are always in agreement.

### REQ-9 — Dashboard wiring
- `lib/screens/admin/dashboard_screen.dart:566` becomes `page: AuditLogTab(api: _api),` (replacing `const AuditLogTab()`); after the change, grep finds **zero** `const AuditLogTab()` in `lib/` and `test/`. No navigation-entry changes (entry :559-566 stays unconditionally registered — capability culling is sibling B6-1a scope, §6).

## 5. Risks and notes

- **R1 (response shape)**: no in-repo schema for `/api/v1/audit/events`; the mapping (REQ-5) follows the cross-repo validation (`b6-1a-validation-audit-events-response-shape.md`) with defensive fallbacks, so the widget fixtures must use **real-shape** rows (`id/type/outcome/timestamp/...`), not ring-shaped ones — otherwise AC-1 passes against invented fixtures while the real integration renders `-` columns (the sibling validation's central finding).
- **R2 (i18n regression)**: changing the subtitle/empty-state copy without the zh catalog entries regresses zh users (unlisted keys fall back to English source) — REQ-6 mandates atomic key+zh updates; existing zh scan enforces it.
- **R3 (flag testability)**: a compile-time `kDebugMode` alone cannot exercise the off-branch in a debug test run — REQ-8 requires an overridable single flag.
- **N1 `[PROPOSED]` preserved (no scope expansion)**: `trace_id` request injection has no mechanism in this repo (only error-body parse at `setup_api.dart:215`) — not implemented; `tenant_id` from claims depends on B4-1 — not implemented (sibling direction B6-1 tenant-scoping covers it). The tab's query stays exactly `{'limit': '100'}`; any future param addition is a proxy-log leakage review point per the sibling design.
- **N2**: the audit-log navigation entry stays unconditionally registered (no capability gate in this direction — sibling B6-1a REQ-5/REQ-6 covers gating; deployments without the route surface the tab's error state instead of a hidden entry).
