## 3. Requirements

### REQ-1 — Zero audit references in `lib/screens/portal/` (codified repo guard)
The portal module (33 files, including the `portal_api.dart` re-export shim) keeps **zero** case-insensitive `audit` occurrences — no imports, no identifiers, no methods, no path literals, no doc-comment mentions. This invariant is currently true at HEAD and must be **codified as a guard-suite scan** so any future regression (e.g., a naive implementer adding `AuditReadClient` wiring or an `/api/v1/audit/*` literal to the Activity tab) fails CI.

- New scan in `test/audit_contract_guard_scans.dart` with scan id **`portal-audit-boundary`**: for every `.dart` file under `lib/screens/portal/` (relative prefix `screens/portal/`), a case-insensitive `audit` occurrence anywhere in the source (identifiers, comments, literals) is a violation. Wired into `scanLibDirectory` alongside scans 1/2/4/5 (per-file call, early-return `const []` for files outside the portal module).
- Green-against-tree assertion in `test/audit_contract_guard_test.dart` (new group, following the scan-5 pattern at :170-:310): `scanLibDirectory(packageLibDir())` filtered to scan `portal-audit-boundary` yields zero violations against the live tree.
- Fail-closed mutation probes in `test/audit_contract_guard_mutation_test.dart` (in-memory overrides, never touching files): injecting `AuditReadClient` usage, an `/api/v1/audit/events` literal, or a comment containing `audit` into any `lib/screens/portal/*.dart` copy must trip the scan.

**Testable:** `grep -rn "audit" lib/screens/portal/` → exit 1; `flutter test test/audit_contract_guard_test.dart test/audit_contract_guard_mutation_test.dart` green.

### REQ-3 — SecurityActivityTab issues only `/me` BFF requests — never the audit trio (widget test)
The portal Activity tab must keep reading exactly the two self-service BFF endpoints `PortalSecurityPaths.securityActivity` (`/me/security/activity`) and `PortalSecurityPaths.loginHistory` (`/me/login-history`) — never `/api/v1/audit/events`, `/api/v1/audit/facets`, or `/api/v1/audit/events/{id}`.

### REQ-4 — Timeline read stays on `SnaplinkAdminApi` + `AuditQuery`; default wire exactly `{'limit':'100'}`
The admin timeline (`lib/screens/admin/audit_log_tab.dart`) consumes the audit read exclusively through `AuditReadClient` (`lib/api/audit_read_client.dart`) — `SnaplinkAdminApi.get(AuditReadClient.eventsPath, query: AuditQuery(...).toQueryParameters())` — with the default wire exactly `{'limit': '100'}` (no `tenant_id`, no `trace_id`; both remain `[PROPOSED]`-gated caller-supplied-only per the batch proposal `:10` record). The documented sibling consumer `GovernanceTab._queryAudit` (`:171-195`, user-typed `AuditQuery` on the **same** carrier) is the precedent that *confirms* the carrier — it is never license to move audit reads onto `PortalApi`.
