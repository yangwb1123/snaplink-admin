## 1. Problem statement (verified)

B6-2 acceptance (a) — *login → exactly one credential-bearing `POST /auth/login` with `client_id = sso-admin-console`* — was unpinned for the `SSOAdminClient` leg, and the portal module was the highest-misread surface:

- **S1 gap (SSOAdminClient leg, now closed).** `test/sso_client_test.dart:10-27` asserts the `/auth/login` body **inside the MockClient handler** (`:13-27`; whole-map `expect(jsonDecode(request.body), {...})` at `:16-24`; `client_id` site `:18` — now a compile-time constant reference `SSOAdminClient.firstPartyClientId` at HEAD, `[CORRECTION: the direction calls `:18` a "literal"; at HEAD it is the constant, constant-mode])` — with **no request counter**, so a second credential-bearing POST would pass silently. The landed harness (`test/edge_generation_console_login_test.dart`) counts every request and gates the total: one `login()` ⇒ exactly one credential-bearing `POST /auth/login`; two `login()` calls ⇒ cumulative 2 (the unit-level "无重复" pin, mirroring the hosted-leg retry pin at `test/oidc_login_screen_client_id_test.dart:156` `[CORRECTION: direction cites `:155`; HEAD position is `:156`, with `lastClientId` asserts at `:137`/`:159`]`).
- **Portal misread risk (now pinned).** `PortalApi.login` (`lib/api/portal_api.dart:233-257`) is a token-paste probe: install token → `get('/me')` `:245` → non-200 throw `:247` → rollback `:250-253`; the file contains **zero** `/auth/login` (grep exit 1, executed). The two portal entry points route through it: `_tryResumeSession` `:108` calls `_api.login(` at `:119`, `_login` calls `_api.login(t)` at `:211` (only two call sites in `lib/screens/portal/portal_screen.dart`). Without a guard, an implementer could "fix" B6-2 by adding a login-emission surface to the portal client — the landed negative-boundary guard (`test/edge_generation_portal_negative_test.dart`) makes that red.

## 3. Requirements

Preserved verbatim in substance from the approved source spec (`docs/proposals/b6-2-lib-screens-portal-edge-generation-spec.md` REQ-1 `:53-60` / REQ-2 `:61-70`), scoped to this direction (test-only; zero `lib/` changes; no edits to the count-gated census/client_id/sso files):

### REQ-1 — The portal module is not an edge generator: zero `/auth/login` and zero emission strings (repo guard)
`lib/screens/portal/` (33 files) keeps **zero** `/auth/login` references (path literals, requests, comments) and `lib/` keeps **zero** `auth.login.success` emission strings. `PortalApi.login` stays a `GET /me` probe; the paste/resume entry points (`portal_screen.dart:119/:211`) cannot create spurious or duplicate sink events. **Landed artifact:** `test/edge_generation_portal_negative_test.dart` (two-scope normalized scan; `auth/login` portal-scoped with the 33-file pin; `auth.login.success` lib/-wide recursive walk). **Unchanged:** `lib/api/portal_api.dart:233-257`, `lib/screens/portal/portal_screen.dart:119/:211`.

### REQ-2 — Console emitters: exactly one credential-bearing `POST /auth/login` per login, body `client_id == 'sso-admin-console'` (unit harness, census-compatible)
`SSOAdminClient.login` must issue **exactly one** credential-bearing `POST /auth/login` per call whose decoded body carries `client_id == SSOAdminClient.firstPartyClientId` (constant-mode at HEAD — the two-state rule's constant branch is live since `db6e435`; the pinned-literal branch is the dormant fallback) and a `credential` map carrying the submitted username/password; a second identical call must add exactly one more (cumulative 2 — unit-level "无重复"). No other request may occur during `login()` (no probe). **Landed artifact:** `test/edge_generation_console_login_test.dart` (6 tests: 4 acceptance + 2 binding). **Unchanged:** the hosted leg already pinned at `test/oidc_login_screen_client_id_test.dart:136/:150/:156`.
